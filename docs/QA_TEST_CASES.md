## 1. 테스트 케이스 전체 목록

### 1-A. 구매 Flow 테스트

#### 정상 흐름 (Happy Path)

**TC-PUR-001**
- **분류:** 통합
- **제목:** 구매요청 초안(DRAFT) 생성 정상 처리
- **사전 조건:** ROLL 1 이상 계정 로그인, 구매요청 메뉴 접근 가능
- **테스트 단계:**
  1. 구매요청 메뉴 진입
  2. 신규 구매요청 작성 버튼 클릭
  3. 품목명, 수량(양의 정수), 요청 사유 입력
  4. 임시저장(DRAFT) 버튼 클릭
- **예상 결과:** 상태가 DRAFT로 저장되고 목록에 표시됨
- **실제 결과:** _(빈칸)_
- **합격 기준:** HTTP 201, 상태값 = "DRAFT", 작성자 본인만 조회 가능

---

**TC-PUR-002**
- **분류:** 통합
- **제목:** DRAFT → PENDING 상태 전환 정상 처리
- **사전 조건:** TC-PUR-001 완료 후 DRAFT 상태 구매요청 존재
- **테스트 단계:**
  1. DRAFT 상태 구매요청 상세 진입
  2. "승인요청" 버튼 클릭
  3. 요청 사유 확인 후 제출
- **예상 결과:** 상태가 PENDING으로 변경, 승인권자에게 알림 발송
- **실제 결과:** _(빈칸)_
- **합격 기준:** 상태값 = "PENDING", 이력 로그 기록, 알림 발송 확인

---

**TC-PUR-003**
- **분류:** 통합
- **제목:** PENDING → APPROVED 승인 처리 정상 흐름
- **사전 조건:** PENDING 상태 구매요청 존재, ROLL 0/1 계정 로그인
- **테스트 단계:**
  1. 구매요청 목록에서 PENDING 항목 선택
  2. 상세 페이지에서 "승인" 버튼 클릭
  3. 승인 의견 입력 후 확인
- **예상 결과:** 상태가 APPROVED로 변경, 요청자에게 승인 알림
- **실제 결과:** _(빈칸)_
- **합격 기준:** 상태값 = "APPROVED", 승인자 ID/시각 기록

---

**TC-PUR-004**
- **분류:** 통합
- **제목:** APPROVED → ORDERED 발주 처리
- **사전 조건:** APPROVED 상태 구매요청 존재, ROLL 0/1 로그인
- **테스트 단계:**
  1. APPROVED 상태 구매요청 선택
  2. "발주" 버튼 클릭
  3. 공급업체, 발주수량, 납기일 입력 후 확인
- **예상 결과:** 상태가 ORDERED로 변경, 발주 번호 생성
- **실제 결과:** _(빈칸)_
- **합격 기준:** 상태값 = "ORDERED", 발주번호 자동 채번, 납기일 저장

**TC-PUR-005**

- **사전 조건:** ORDERED 상태 구매요청 존재
- **테스트 단계:**
